## 5. Verificaciones SQL

Por cada compra confirmada se comprueba:

```sql
SELECT stock FROM PRODUCTO WHERE id_producto = ?;
SELECT id_producto, cantidad FROM ITEM_CARRITO WHERE id_carrito = ?;
SELECT id_pedido, estado, modalidad_pago, total, moneda_total
FROM PEDIDO WHERE id_cliente = ?;
SELECT id_pedido, monto
FROM MOVIMIENTO_CUENTA_CORRIENTE m
INNER JOIN CUENTA_CORRIENTE c ON c.id_cuenta_corriente = m.id_cuenta_corriente
WHERE c.id_cliente = ?;
SELECT id_pedido FROM PAGO
WHERE id_pedido IN (SELECT id_pedido FROM PEDIDO WHERE id_cliente = ?);
SELECT clave, estado, http_status, id_pedido
FROM CONFIRMACION_PEDIDO_TRANSFERENCIA WHERE id_cliente = ?;
SELECT id_pedido, id_cuenta_corriente, tipo_mime, id_admin_revision
FROM COMPROBANTE_PAGO WHERE id_cliente = ?;
```

Resultados esperados y verificados:

- `stock` baja de 5 a 3 para cantidad 2.
- `ITEM_CARRITO` queda vacío tras la compra.
- Un único `PEDIDO` con `modalidad_pago = 'TRANSFERENCIA'`, `estado = 'CONFIRMADO'`.
- `DETALLE_PEDIDO` conserva cantidad y subtotal.
- `PAGO` y `MOVIMIENTO_CUENTA_CORRIENTE` quedan vacíos: el pedido no acredita el pago.
- El intento queda `CONFIRMADO/201`; el rechazo queda `RECHAZADO/409`.
- El comprobante queda asociado al `id_pedido` correcto y sin revisión administrativa.
- El segundo cliente no ve el pedido y recibe 404 al consultar la clave ajena.
