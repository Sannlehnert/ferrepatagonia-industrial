# T-S7-09.3 — Solicitud y consulta de crédito para EMPRESA

La vista de cuenta corriente permite que una empresa aprobada comercialmente
envíe una solicitud de crédito y consulte sus solicitudes. La evaluación sigue
siendo manual: enviar o aprobar una solicitud no habilita automáticamente la
cuenta para comprar a crédito.

El botón **Actualizar** consulta tanto la cuenta como el historial de
solicitudes. Al cambiar de sesión se descartan el formulario, el intento y las
respuestas anteriores. Un rechazo definitivo permite corregir y enviar con
otra clave; ante un resultado incierto se conservan los datos y la clave para
reintentar sin duplicar la solicitud.

## Estados visibles

| Estado | Comportamiento |
| --- | --- |
| Aprobación empresarial pendiente o rechazada | Se informa que la empresa no es elegible y no se consulta el endpoint protegido ni se ofrece el formulario. |
| Solicitud pendiente | Se muestra el estado y se impiden envíos duplicados hasta la resolución. |
| Solicitud rechazada | Se informa el rechazo y se permite iniciar una nueva solicitud. |
| Solicitud aprobada | Se muestra el límite y plazo autorizados cuando están disponibles; se aclara que la habilitación de cuenta es independiente. |
| Cuenta habilitada | El estado comercial existente muestra la habilitación y disponibilidad de crédito, sujeta a validación en cada compra. |

## Evidencia automática

Ejecutar desde `frontend/`:

```sh
npm test -- --test-name-pattern="solicitudes propias|empresas no aprobadas|advertencia de evaluación"
npm run type-check
```

Los casos automatizados verifican la ruta propia y la clave de idempotencia,
que las empresas no aprobadas no consultan solicitudes, y que la interfaz no
promete aprobación automática.

Con el backend compilado y Chromium instalado, desde la raíz:

```sh
node backend/test/helpers/run-e2e.cjs e2e/account/credit-request.mock.spec.ts e2e/account/credit-request.real.spec.ts
```

El ejecutor crea y elimina una base MariaDB aislada. Las pruebas cubren cambios
de sesión con respuestas diferidas, rechazos y reintentos, y decisiones reales
de ADMIN consultadas mediante **Actualizar** sin recargar la página.

## Comprobación manual sugerida

1. Iniciar sesión con una empresa con aprobación comercial pendiente: la vista
   debe indicar que no es elegible y no mostrar el formulario.
2. Iniciar sesión con una empresa aprobada sin solicitudes: completar monto y
   plazo y enviar; verificar que aparezca como pendiente.
3. Mientras la solicitud siga pendiente, comprobar que no se permita enviar
   otra.
4. Resolver desde el flujo ADMIN y actualizar la vista: comprobar los estados
   rechazada o aprobada. En el caso aprobado, verificar que la cuenta no se
   presente como habilitada automáticamente.
